# Публичный каталог

`/masters` — серверный поиск по имени/описанию, направление, диапазон цены,
сортировка и страницы по 12 карточек. Форма применяется кнопкой «Найти»;
условия и страница сохраняются в URL, работают обновление и история браузера.
Новый поиск сбрасывает номер страницы. Некорректные параметры показывают ошибку
до запроса каталога. Цена относится к подходящим активным предложениям мастера.

`/services` — поиск услуг и направление. Переход из услуги открывает мастеров
этого направления; отдельного фильтра по конкретной услуге у API пока нет.
Стоимость и длительность индивидуальны и показаны в профиле мастера.

`/masters/:id` — описание, адрес, услуги, портфолио с увеличением и отзывы.
У разделов независимая пагинация. Диалог фотографии закрывается кнопкой или
Escape и возвращает фокус к исходной фотографии. Без рейтинга показывается
«Пока без отзывов», без аватара — монограмма; демо-профили явно помечены.
Скрытый/удаленный профиль дает ссылку обратно в каталог.

Кнопка «Свободное время» получает интервалы из настоящего availability API.
Дата ограничена сегодня..90 дней вперед по календарю мастера; UTC интервалы
отображаются в его IANA timezone с UTC offset. «Перейти к записи» сохраняет
выбранную дату и услугу. Оформление и кабинеты описаны в BOOKING.md.

TanStack Query кэширует публичные запросы на 30 секунд, категории на 5 минут;
AbortSignal передается fetch при смене запроса/уходе со страницы. Загрузка,
ошибка с повтором и пустой результат отображаются отдельно. Демо-данные не
подменяют недоступный API. Нужен `VITE_API_BASE_URL` из корневого `.env`.

## Проверки

`npm test` включает сценарии фильтров/URL/пагинации, валидации URL,
восстановления после ошибки и отсутствующего профиля.

`e2e/catalog.spec.mjs` проверяет реальный API/PostgreSQL, фильтрацию цены и
направления, сортировку, обновление/историю, услуги, расписание, галерею и
горизонтальное переполнение на 320/375/768/1440px; сохраняет PNG на 375/1440px.
В CI перед браузером выполняется `python -m scripts.seed_browser` из backend.
Скрипт допускает только `TEST_DATABASE_URL` PostgreSQL с именем БД `*_test`.
Его 14 профилей явно демонстрационные. Для сценариев кабинетов нужен случайный
приватный BROWSER_TEST_PASSWORD: он задает доступ только к одноразовым тестовым
аккаунтам CLIENT/MASTER/ADMIN и генерируется с маскировкой в CI.
Нельзя использовать этот тестовый наполнитель для production.
