# Темы, движение и доступность

Цветовая тема выбирается в шапке: «Авто», «Светлая», «Темная». Theme Context
следит за настройкой устройства в режиме Auto, сохраняет явный выбор в
`masterly:theme` и синхронизирует открытые вкладки. При недоступном storage тема
все равно переключается. Внешний `/theme-init.js` выполняется до React/CSS,
чтобы применить сохраненную темную тему без светлой вспышки. Токены обеих тем
и адаптивные состояния находятся в `src/polish.css`.

Доступность интерфейса:

- skip-link фокусирует основной контент; после SPA-перехода фокус переходит
  к заголовку, после смены раздела/страницы — к результатам; дата/услуга не
  перехватывают фокус при обычном вводе;
- мобильное меню переводит фокус к первой ссылке; Escape возвращает его к
  кнопке, уход из шапки закрывает меню;
- формы редактирования фокусируют первое поле, закрытие возвращает к исходной
  кнопке; удаление/отключение имеет подтверждение и возврат фокуса;
- ошибки операций фокусируют сводку; конкретные ошибки полей связаны с полями
  через aria-describedby и отмечены aria-invalid. Остальные ошибки описываются сводкой;
- переход к подтверждению записи фокусирует заголовок; серверный результат
  сопровождается сообщением статуса, обновление посещения объявляется отдельно;
- галерея использует native modal dialog, Escape и возврат к фотографии;
- скелетоны декоративны (aria-hidden), сообщение загрузки имеет role=status;
  ошибка, пустая выдача и успешный ответ остаются разными состояниями.

CSS анимирует появление блоков/карточек, подтверждения и success-state;
IntersectionObserver + Web Animations добавляют короткое появление секций в
viewport. До наблюдения и без JS контент остается видимым. Фото увеличиваются
только при hover-capable pointer. `prefers-reduced-motion: reduce` отключает
CSS motion, shimmer и hover сдвиг; активные viewport-анимации отменяются при
смене настройки устройства. Skeleton не имитирует готовые данные.

Кабинеты и запись загружаются через React.lazy/Suspense, а не в основном
публичном JS. Полный результат build и реальные размеры следует брать из
вывода конкретного проверенного коммита, а не из оценок.

## Проверки

`e2e/accessibility.spec.mjs` применяет @axe-core/playwright с тегами wcag2a,
wcag2aa, wcag21a, wcag21aa, wcag22aa и best-practice, без исключения элементов
или отключения отдельных правил. Полный JSON сохраняется как attachment.
Проверяются публичные страницы в обеих темах на 375/1440px, dark-кабинеты
CLIENT/MASTER/ADMIN, открытые формы, gallery, loading/retry/empty-state,
keyboard focus, Escape и reduced motion. Основные бизнес-E2E дополнительно
проверяют ширины 320/375/768/1440.

Автоматический аудит не доказывает полного соответствия WCAG и не заменяет
ручную проверку screen reader, zoom, сложных альтернатив изображений и всех
возможных данных. Поля incomplete в axe JSON требуют человеческой оценки;
визуальные снимки проверяются отдельно. Полный production-аудит текущих
локальных изменений требует отдельного развертывания.

Локальная проверка 21.11.2026: 25 основных E2E прошли, в том числе новый профиль
на 375/768/1440px без axe violations; 6 дополнительных сценариев прошли в
Chromium, Firefox и WebKit. Lighthouse 13.6.0 дал Accessibility 100/100 для
профиля на локальном Vite-сервере с мобильной эмуляцией. Это оценка конкретного
локального прогона, не результат production performance-аудита. Анимация появления
секций использует смещение без уменьшения прозрачности текста, сохраняя контраст.
