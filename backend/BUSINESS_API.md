# Business API: catalog, schedule and booking

Этап 7. Полный текущий контракт генерируется FastAPI: /openapi.json и /docs. Приложение содержит 60 операций HTTP, включая ранее реализованную авторизацию. UI каталога подключен на этапе 8 (frontend/CATALOG.md); UI оформления записи еще не реализован, production-деплоя нет.

## Публичные данные

GET /api/v1/categories, /services, /masters возвращают {items,total,page,page_size}; page>=1, page_size<=50. Каталог мастеров поддерживает search, category_id, min_price, max_price, sort=name|price_asc|price_desc|rating. Фильтры, сортировка и пагинация выполняются SQL. Цена отбирается по подходящим активным предложениям, скрытые профили и отключенные пользователи не показываются. При отсутствии отзывов rating=null и review_count=0, без фиктивных оценок.

GET /masters/{id}, /masters/{id}/services, /portfolio, /reviews - профиль и его ресурсы. GET /masters/{id}/availability?master_service_id=UUID&date=YYYY-MM-DD - реальные слоты на выбранную дату в IANA timezone мастера. Дата в каталоге мастеров пока не является фильтром доступности: для проверки времени используется отдельный availability endpoint.

## Работа мастера

PATCH /master/profile обновляет bio/timezone/address/avatar_url/is_published. Валидируется IANA timezone и безопасная схема image URL. При действующих записях нельзя менять часовой пояс; абсолютное время и timezone snapshot истории сохраняются.

/master/services: GET/POST, /{id}: PATCH/DELETE (деактивация предложения, без удаления истории). Цена Decimal, длительность 15–720 минут, кратна 15. Чужой объект возвращает 404. /master/portfolio: GET/POST, /{id}: PATCH/DELETE; фото снабжено источником/лицензией, сервер не скачивает произвольные пользовательские URL.

/master/schedules: GET/POST, /{id}: PATCH/DELETE. weekday=0..6 (понедельник=0), местные часы кратны 15 минутам, без offset, starts_local<ends_local. Ночные интервалы не поддерживаются. /master/schedule-exceptions: GET/POST, /{id}: PATCH/DELETE. Исключение полностью заменяет регулярный график даты: выходной без часов или один рабочий интервал. Изменение/удаление графика запрещено с 409, если затрагивает действующую CONFIRMED-запись.

## Создание записи

POST /api/v1/bookings требует CLIENT, Authorization: Bearer и Idempotency-Key: UUID. Body:

```json
{"master_service_id":"00000000-0000-4000-8000-000000000001","starts_at":"2030-01-08T09:00:00+05:00"}
```

UUID/дата выше - только иллюстрация. Для рабочего запроса берется starts_at из availability. Цена, длительность, master_id и статус не принимаются от клиента. На сервере устанавливаются snapshot названия/цены/длительности/часового пояса. Новая запись дает 201; повтор с тем же ключом и семантически тем же временем возвращает ту же запись с 200; иной payload при прежнем ключе - 409 IDEMPOTENCY_CONFLICT. Повтор отмененной записи по прежнему ключу не создает новое посещение.

В одной транзакции блокируется клиент (FOR NO KEY UPDATE, совместимо с FK KEY SHARE) для защиты идемпотентности, затем профиль мастера; после ожидания блокировки предложение перечитывается и доступность рассчитывается заново. Все изменения графика и предложения используют ту же блокировку мастера. EXCLUDE PostgreSQL страхует пересечения независимо от приложения. Два разных клиента не могут успешно занять один интервал. Ошибки не раскрывают SQL или чужие данные. Поврежденный JSON дает 400 JSON_INVALID, корректный JSON с неверными полями — 422.

Доступность: сегодня..90 дней вперед по местному календарю мастера; будущие starts_at, сетка 15 минут, реальная длительность в абсолютных минутах. Несуществующие при DST местные минуты исключаются через UTC round-trip, повторяющиеся часы представлены разными UTC instants. Соседние рабочие окна непрерывны, перерывы не перекрываются услугой. Результаты UTC+timezone; интерфейс должен явно отображать timezone/offset повторяющихся часов.

GET /bookings - собственные CLIENT-записи; /master/bookings - записи к текущему MASTER; /admin/bookings - ADMIN. GET /bookings/{id} доступен только участникам/ADMIN, чужой ID дает 404. PATCH /bookings/{id}: CANCELLED до начала, COMPLETED только своим MASTER или ADMIN после окончания. Обратные переходы запрещены, повтор того же перехода идемпотентен. ADMIN при отмене должен указать причину. Отмена освобождает слот.

## Отзывы, избранное, управление

/favorites: GET; /favorites/{master_id}: PUT/DELETE, только CLIENT, идемпотентно. /reviews: POST после собственной COMPLETED-записи, один отзыв на запись; /reviews/{id}: PATCH своего CLIENT-отзыва, DELETE автора/ADMIN. Рейтинг вычисляется из данных, не задается в профиле вручную.

ADMIN: CRUD /categories и /services; /admin/categories и /admin/services показывают в том числе неактивные записи. Удаление используемой категории/услуги дает 409, вместо потери истории следует деактивация. /admin/users GET/PATCH is_active, /admin/masters GET/PATCH is_published. Назначения ADMIN через публичный API нет; блокировать ADMIN из UI нельзя, чтобы не потерять административный доступ.

## Миграции и проверки

Ревизия 004 добавляет bookings.timezone_snapshot с backfill из существующих профилей; 001–003 не переписываются. Выполнить alembic upgrade head до запуска обновленного API. В тестовой БД проверяются downgrade/upgrade всех четырех границ.

Интеграционные тесты требуют TEST_DATABASE_URL с суффиксом _test и очищают только эту одноразовую БД. Проверяются реальные HTTP-запросы, конкурентные подключения, идемпотентность, календарь/DST, права/IDOR, отзыв, избранное, CRUD, SQL pagination и число запросов каталога. Результат CI и планы предыдущих индексов сохраняются в database-verification. Браузерный сценарий записи будет добавлен вместе с UI этапа 9; текущий Playwright проверяет авторизацию.
